# 拼豆生成 — 产品概览（PRD）

> 适用范围：BeadForge 创作域（Create / 发现 / 图纸市场）。本文档不覆盖材料商城、订单、社区动态等周边模块。

## 一、产品定位

BeadForge 是一站式 **拼豆图案创作 + 分享 + 交易** 平台。"拼豆生成"指用户从一个空白画布或一张参考图，得到一份可直接照着摆豆的 **彩色像素网格（grid）**。

核心价值：

1. **降低创作门槛**：手不会画、不会用 PS 的用户也能 30 秒出图
2. **三条创作路径互通**：手动、图片转换、AI 生图三种入口产出同一份数据结构（`grid[][]`），后续编辑、保存、发布完全一致
3. **拼豆友好**：固定 24 色调色板，直接对应市售豆色卡，避免"图纸好看但买不到豆"的问题

## 二、用户画像

| 画像 | 占比预估 | 关键诉求 | 痛点 |
|---|---|---|---|
| **入门玩家**（学生 / 手工小白）| 50% | 想做但不会设计；要找现成图纸 | 网上图纸格式杂、调色板不一致、买不到对应颜色 |
| **进阶创作者**（熟手 / 二创爱好者）| 35% | 把脑子里的角色 / Logo 变成拼豆图 | 手画方格纸费时；调色靠肉眼 |
| **半商业卖家**（开店 / 接单）| 10% | 批量出图、销售图纸赚钱 | 缺正版调色映射；图纸格式不能复用到生产端 |
| **教师 / 亲子用户** | 5% | 给孩子做主题课件 / 亲子手工 | 需要简单可印的成品图，不要太多配置项 |

## 三、核心创作路径

三条入口，**最终落地物相同**：一个 `cols × rows` 的 hex 颜色网格。

```
                       ┌──────────────────┐
                       │  EditorScreen    │
                       │ （统一画布编辑） │
                       └────────▲─────────┘
                                │ grid[][]
       ┌────────────────────────┼────────────────────────┐
       │                        │                        │
   ┌───┴────┐             ┌─────┴─────┐            ┌─────┴─────┐
   │ 手动   │             │ 图片转换  │            │ AI 文生图 │
   │ manual │             │ image     │            │ ai        │
   └────────┘             └───────────┘            └───────────┘
   空画布起步              本地或上传图           输入 prompt
   工具：笔/橡皮/        服务端像素化           调豆包 Seedream
   填充/吸管             双线性 + 24 色         → 像素化 → grid
```

> 当前 `image` 模式在前端是 mock 占位（见 `EditorScreen.tsx:138`），未真正接图片转换；服务端 `AiController` 的像素化函数已经具备能力，只缺一个"上传图 → 同样 pipeline"的接口。

## 四、用户故事（User Stories）

按角色 + 价值点写，验收标准可直接落到 e2e 测试。

### S1 — 入门玩家想要 30 秒出一张猫咪图

> **作为** 入门玩家
> **我想** 输入"可爱的小猫咪"就拿到一张拼豆图
> **以便** 我直接照着摆豆，不用学画图

**验收**：
- 在创作入口选择 "AI 生图" 模式 → 输入框聚焦
- 输入 prompt → 点生成 → 5–15 秒内得到 16×16 grid
- 生成图最多用 24 色，且每色都在调色板里
- 生成后立即进入编辑器，可继续修改

### S2 — 进阶创作者想把自家照片转成拼豆图

> **作为** 进阶玩家
> **我想** 上传一张照片就得到拼豆版
> **以便** 我能给宠物 / 房子 / 头像做纪念

**验收**（image 模式真实化后）：
- 选择 "图片转换" → 拍照 / 选相册
- 自动按选定网格尺寸像素化（16×16 / 24×24 / 32×32）
- 透明区识别（接近纯白背景自动透明）
- 进入编辑器后可手动调色

### S3 — 进阶创作者想精修 AI 生成结果

> **作为** 进阶玩家
> **我想** AI 出图后再补一笔 / 改一格颜色
> **以便** 让最终图纸更符合我的审美

**验收**：
- 编辑器提供笔 / 橡皮 / 填充 / 吸管四个工具
- 支持撤销 / 重做（至少 30 步）
- 切换工具不丢已绘内容

### S4 — 半商业卖家想发布并出售图纸

> **作为** 卖家
> **我想** 把作品打包成图纸上架
> **以便** 别人付费下载，我赚拼豆币

**验收**：
- 我的作品 → 选一个 → "发布为图纸"
- 填标题 / 分类 / 价格（≤ 0 自动免费）
- 上架后出现在图纸市场，他人购买后能下载到 `grid` 数据

### S5 — 教师想要可打印的图纸

> **作为** 教师
> **我想** 把生成图导出成 PDF / 高清 PNG
> **以便** 打印分发给学生

**验收**（待实现）：
- 详情页 "导出" → 选格式（PNG / PDF / 商家色卡）
- PDF 自带每色 → 商家货号映射表
- 网格上有坐标编号，方便边对照边摆

## 五、关键流程图

### 5.1 创作主流程

```
首页 ─→ 创作 Tab ─→ CreateScreen
                       │
                       ├─ 选模式（manual / image / ai）
                       ├─ 选尺寸（16×16 / 24×24 / 32×32 / 自定义）
                       │
                       └─→ EditorScreen
                              │
                              ├─ [ai] 输入 prompt → POST /ai/generate-image
                              ├─ [image] 上传图 → POST /image/pixelate（待建）
                              ├─ [manual] 空白起步
                              │
                              ├─ 工具栏编辑（笔/橡皮/填充/吸管）
                              ├─ 撤销/重做（本地栈）
                              │
                              └─→ 保存：POST /designs（DRAFT）
                                   ├─→ 发布作品：PUT /designs/{id} status=PUBLISHED
                                   └─→ 上架图纸：POST /patterns/publish
```

## 六、模块边界

| 在范围内 | 不在范围内 |
|---|---|
| Create / Editor / AI 生图 / 调色板 | 材料商城、订单流程 |
| Design / Pattern 实体与生命周期 | 钱包 / 充值 |
| 图纸导入导出格式 | 社区 Feed / 评论 / 关注 |
| 调色板与商家色卡映射 | 通知中心、私信 |

## 七、非功能性要求

| 维度 | 目标 | 当前状态 |
|---|---|---|
| **AI 生图响应** | P95 ≤ 15s | 未度量（取决于豆包返回） |
| **像素化精度** | 24 色调色板覆盖 95% 常见图案 | ✅ 实测合格 |
| **画布渲染** | 32×32 网格滚动不掉帧 | ✅ |
| **撤销栈深度** | ≥ 30 步 | ✅ `MAX_HISTORY=30` |
| **图纸数据兼容** | 老版本图纸不能因升级失效 | 待规范（见 03 数据模型） |
| **AI 成本** | 每张 < ¥0.5 | 取决于豆包定价；建议加用户限频 |

## 八、依赖与限制

- **豆包 API（火山方舟 Ark）**：图来源、定价、限流由对方控制；密钥存 `t_api_config`
- **24 色调色板**：硬编码于后端 `AiController.PALETTE`、前端 `EditorScreen.PALETTE_ROWS`，两端必须保持一致
- **Java 8 + Spring Boot 2.7**：决定了不能用 Java Records、不能用 SpringDoc v2
- **本地文件存储**：`/uploads` 落本地磁盘，重启容器丢图（参见 06 路线图 OSS 化项）
